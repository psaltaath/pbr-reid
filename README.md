# PBR-ReID — Learning Discriminative Prototypes via Boundary Repulsion MixUp

Reference implementation of **PBR-ReID** (WACV 2027): a prototype-based object
re-identification framework on a DINOv3 backbone, with **Boundary Repulsion
MixUp (BRM)**, a geometry-aware regularizer that builds an explicit boundary
proxy between confusable identities and repels their features from it.

<p align="center">
  <img src="docs/figs/methodology1.png" width="85%">
</p>

* One learnable prototype per identity, jointly optimized with the encoder; the
  prototype similarity matrix **S** exposes the confusable identity pairs at
  every step.
* Objective (Eq. 1): feature-prototype triplet **L_fpt**, batch-hard feature
  triplet **L_bht**, Fréchet-mean center loss **L_cen**, unit-norm regularizer
  **L_norm**, and **L_BRM** (attraction + repulsion from the boundary proxy +
  adaptive-margin prototype separation).
* Two-stage protocol: prototype warmup (frozen backbone) → EMA-stabilized joint
  fine-tuning with a dual learning-rate schedule.
* Prototypes are dropped at test time: plain cosine nearest-neighbour retrieval,
  no re-ranking, no camera embeddings.

## Installation

```bash
git clone --recursive https://github.com/<org>/pbr-reid.git && cd pbr-reid
uv sync                      # or: pip install -e . (Python >= 3.12, PyTorch >= 2.8)
```

**DINOv3 weights.** The backbone code is the `facebookresearch/dinov3` submodule
(`third_party/dinov3`); the pretrained checkpoints are gated by Meta and must be
downloaded from https://github.com/facebookresearch/dinov3 into
`weights/dinov3/` (keep the official filenames, e.g.
`dinov3_vitb16_pretrain_lvd1689m-73cec8be.pth`). Point elsewhere with
`model.dinov3_weights_dir` or `export PBR_DINOV3_WEIGHTS=/path`.

**Other encoders (Table 3).** `uv run scripts/download_backbones.py` fetches the
CLIP ViT-B/16, ImageNet ViT-B/16 and DINOv2 ViT-B/14 weights into `weights/backbones/`.

**Datasets.** Place them under `data/` (or `export PBR_DATA_ROOT=/path`) with the
folder names listed in [docs/DATASETS.md](docs/DATASETS.md).

## Training and evaluation

```bash
uv run train.py market1501                 # paper recipe; logs + checkpoints in runs/market1501
uv run train.py veri                       # vehicles use the 192x384 geometry (configs/datasets/veri.yaml)
uv run train.py market1501 vitl16          # stack any configs/**.yaml by name
uv run train.py dukemtmc -f configs/ablations/losses/l5_mixup.yaml --system.seed 123
uv run eval.py market1501 --checkpoint runs/market1501/latest.pth [--rerank]
```

`configs/base.yaml` holds the paper's implementation details (Sec. 4.1): batch
8 identities × 4 instances, 384×192 inputs, 200 epochs with 10 warmup epochs,
AdamW, encoder LR 1e-5 → 1e-7 (cosine), prototype LR 1e-1 (step 15), EMA 0.999,
λ_fpt = λ_bht = 1, λ_cen = 0.5, λ_norm = 0.005, λ_BRM = 0.4, τ = 0.7, α = 0.4,
m_BRM = 0.5, β = 0.7, γ_sep = 1.5. Every knob maps to a paper symbol in
[docs/CONFIG.md](docs/CONFIG.md); all ablations of the paper are shipped as
override files under `configs/ablations/` (generated by
`configs/ablations/generate.py`).

Training on one RTX 4090 takes roughly a day for Market-1501 with ViT-B/16.

## Repository layout

```
train.py / eval.py        entry points
configs/                  base.yaml (paper recipe), datasets/, backbones/, ablations/
config/                   typed configuration (dataclasses + YAML + CLI overrides)
datasets/                 Market-1501, DukeMTMC, MSMT17, CUHK03-NP, IUST, VeRi-776, VehicleID loaders + PK sampler
models/                   DINOv3 / DINOv2 / CLIP / ImageNet encoders, PrototypeReID
losses/                   L_fpt, L_cen, L_norm, L_bht, MixUp + BRM, adaptive-margin separation, Table 4 heads
training/                 two-stage Trainer, optimizer factories, data pipeline
evaluation/               mAP / CMC, k-reciprocal re-ranking
tools/                    figure scripts (retrieval comparison, confusable-pair KDE, prototype t-SNE)
scripts/                  download_backbones.py, reproduce.sh
tests/                    CPU unit tests (uv run pytest)
third_party/dinov3        DINOv3 submodule
```
